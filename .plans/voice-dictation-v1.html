A · Decisions you're most likely to tweak

Each card shows the pick and one real alternative. Reply with the mono line to flip it.

Cleanup transport: drive the app-server from Swift, or wrap the Codex SDK?

weakest part
Both keep one warm Codex process for the life of the app. The Codex SDK is a TypeScript wrapper that spawns exactly this app-server underneath, so the question is whether Swift speaks the JSON-RPC directly or a Bun sidecar does it and exposes a local socket.
pickSpawn codex app-server from Swift, JSON-RPC over stdio
  • initialize once, thread/start once with your prompt as developer instructions and sandbox: read-only
  • Each utterance is turn/start with the raw transcript; read item/agentMessage, stop on turn/completed
  • Fresh thread every 50 utterances or 10 min idle so history never bloats
  • Types from codex app-server generate-ts as the reference for the Swift Codable structs
keep app-server from swift
alternativeBun sidecar on the Codex SDK
  • @openai/codex-sdk startThread() / run() in a tiny Bun process, local Unix socket to the Swift app
  • Less JSON-RPC plumbing in Swift, but a second runtime and a second process to supervise
  • Worth it only if the app-server wire format proves awkward from Swift
use a bun sdk sidecar

Live preview while you talk: how the HUD gets its text

fixes the wispr flow wait
The document only ever receives the cleaned text once, on release. But you should see the raw words appear as you speak so you stop talking in chunks to check it heard you. Two ways to feed that preview.
pickRe-run Parakeet v2 on the growing buffer
  • Every ~500 ms while held, transcribe everything captured so far and replace the HUD text
  • One model, best accuracy, and the final pass on release is the same call
  • Tail words revise as context arrives, which reads like live captions
  • Cost grows with utterance length; on M3, 20 s of audio still transcribes in well under the tick
keep v2 re-run preview
alternativeParakeet EOU 120M streaming for preview, v2 for final
  • True streaming partials at 160–320 ms chunks, constant cost regardless of length
  • Smaller model, so the preview is rougher than what gets pasted
  • Two models loaded, two code paths; the switch if the re-run approach lags on long dictation
use eou streaming for preview

HUD placement and memory

Wispr Flow's floating window ends up wherever it likes. This one has a home, can be moved, and knows when to go home.
pickHome is bottom-centre; remembered per screen layout; reset on change
  • Default: horizontally centred on the screen with the keyboard focus, ~80 pt up from the bottom edge, above the Dock
  • Draggable anywhere. Position is saved keyed by a fingerprint of the current display arrangement (screen ids, frames, main display)
  • Any change to that fingerprint (dock, undock, resolution, monitor added or removed) discards the saved spot and returns to home
  • If a saved position is off-screen for any reason, home wins
  • Menu item "Reset HUD position" for when you just want it back
keep hud home + per-layout memory
alternativeAlways home, never movable
  • Zero state, zero surprises, one fewer thing to get subtly wrong
  • Loses the ability to nudge it out of the way of a status bar or a video
hud fixed at home

Where the prompt and vocabulary live

You want to tune how it handles your speech and your project names. That should be an edit-and-save loop, not a rebuild.
pickPlain files in ~/.config/voice/
  • prompt.md is the system prompt, sent verbatim
  • vocab.txt, one term per line, appended to the prompt and passed to Parakeet as custom vocabulary
  • config.json for hotkey, backend, model. All re-read on each utterance
keep config files
alternativeSettings window in the app
  • SwiftUI form behind the menu bar item
  • Nicer for discovery, more code, still needs a store underneath
  • Can be added later on top of the files
add a settings window

Cleanup backend and model

Codex sub usage on a small model is effectively unlimited for this workload, and Claude usage is worth keeping for Fable and Opus. Both live behind one Cleaner protocol regardless.
pickCodex, gpt-5.6-luna
  • Warm app-server as above; model set per thread in config.json
  • Reasoning effort minimal, no tools, prompt says output only the cleaned text
  • Claude never called by default
keep codex luna default
alternativeClaude fallback via claude -p
  • ClaudeCleaner spawns claude -p --model sonnet --tools "" --system-prompt-file prompt.md per utterance
  • Used only if "backend": "claude" or the app-server is down and "fallback": true
  • Built in M3, not M2
fall back to claude when codex is down

Delivering the text

Needs the Accessibility permission either way. Typing leaves the clipboard alone, which matters more than raw speed for a tool you use all day.
pickType it with CGEvent unicode
  • Posts keyboard events carrying the text in 20-unit chunks, newlines as Return
  • Clipboard is never touched
  • If Accessibility is missing, the HUD says so and nothing is delivered
keep typed delivery
alternativeClipboard swap + synthetic ⌘V
  • Faster for long text, but overwrites the clipboard even with a restore
  • Rejected: clobbering the clipboard would annoy fast
paste instead of type

B · Sequence

Each milestone ends with something you can use. Nothing in M2 onward changes what M1 built.

M0skeleton
Menu bar app that builds from the terminal
  • Package.swift, executable target, AppKit NSStatusItem, no storyboard
  • scripts/bundle.sh wraps the binary in Voice.app with an Info.plist carrying mic and accessibility usage strings, then ad-hoc codesigns
  • Hotkey listener via CGEventTap on right ⌥, menu icon changes while held
swift build && scripts/bundle.sh && open Voice.app shows an icon that reacts to the key
M1raw dictation
Hold, speak, see it appear, release, raw transcript pastes
  • Recorder captures 16 kHz mono float into a buffer while held
  • FluidAudio loads Parakeet v2 at launch; preview tick re-transcribes the buffer every ~500 ms into the HUD; final pass on key-up
  • HUD: borderless non-activating NSPanel, bottom-centre home, draggable, position remembered per display layout and reset when the layout changes
  • Paster delivers it; latency for each stage logged to stderr
Usable as a dumb dictation tool, and already better than the wait-then-appear experience
M2cleanup
The intelligence pass
  • Cleaner protocol, CodexCleaner owning a warm codex app-server child and one thread
  • Default prompt.md written on first run: strip fillers and restarts, keep meaning and tone, never answer or summarise, output only the text
  • Short utterances under a configurable word count skip cleanup
The hero example above works end to end, with cleanup latency logged
M3tuning loop
Make it yours
  • vocab.txt feeds both Parakeet custom vocabulary and the prompt
  • history.jsonl with raw, clean, timings, backend, so you can see what the prompt is getting wrong
  • ClaudeCleaner per-spawn fallback and the backend switch
Edit a file, dictate again, see the difference
M4feel
Polish that earns its place
  • HUD states: listening, cleaning, done, and a subtle marker when the raw text was pasted because cleanup failed
  • Start and stop sounds, cancel with Esc while held
  • Login item, menu with "edit prompt", "open history", "quit"
Permissions are the only fiddly bit. Microphone and Accessibility prompts are tied to a signed app bundle, not a bare binary. That's why M0 includes the bundle script. If macOS refuses the ad-hoc signature for Accessibility, the fallback is a self-signed certificate from Keychain Access, still no Xcode.

Default prompt.md

Written once on first launch, never overwritten. Roughly: you are a dictation cleaner; remove fillers, false starts, repeated words and self-corrections, keeping the last version of anything the speaker corrected; keep the speaker's wording and tone; fix punctuation and casing; expand nothing, answer nothing, add nothing; output only the cleaned text. Followed by the vocabulary list.

Things to verify in M0 before anything else

  • FluidAudio resolves and builds under Swift 6.4 with strict concurrency
  • Parakeet v2 downloads to ~/.cache/fluidaudio on first run, offline after
  • Ad-hoc signed bundle triggers the mic prompt
  • CGEventTap gets right ⌥ events once Accessibility is granted
  • Re-running v2 on a 20 s buffer stays under the 500 ms preview tick on M3; if not, flip to EOU streaming
  • HUD panel takes no keyboard focus and never steals the cursor from the target app
  • codex app-server on stdio accepts initialize and answers a turn/start on a tool-free, read-only thread
  • Not doing: live typing into the document, multi-language, a settings UI, Whisper fallback

Timeouts and failure

If the cleaner exceeds its timeout or exits non-zero, paste the raw transcript and note it in history. Dictation should never silently swallow what you said.
